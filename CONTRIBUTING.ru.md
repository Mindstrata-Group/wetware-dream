# Как участвовать

[English](CONTRIBUTING.md) — основная версия.

Спасибо, что помогаете! Прочитайте [AGENTS.ru.md](AGENTS.ru.md) (правила для
людей и ИИ-агентов), [docs/TESTING.ru.md](docs/TESTING.ru.md) (как тестировать)
и [AI_POLICY.md](AI_POLICY.md).

## Путь вклада

1. **Возьмите или откройте задачу (issue).** Напишите, что меняется для
   пользователя. Новичкам — метки `good first issue` и `recipe`; в
   [docs/recipes/](docs/recipes/) у каждого рецепта список файлов и готовый
   промпт для агента.
2. **Сделайте форк** и ветку.
3. **По желанию — раннер на своём компьютере**, чтобы CI форка шёл у вас:
   три шага в [runner/README.md](runner/README.md).
4. **Внесите изменение с тестом.** Фикс бага начинается с падающего теста.
5. **Запустите `make check`** до зелёного (или получите зелёный CI в форке).
6. **Откройте PR по шаблону:** что меняется для пользователя, какие тесты,
   вывод `make check`, использовался ли ИИ.
7. **Подпишите CLA** — бот попросит один раз, одной строкой в комментарии
   ([зачем](CLA.md): у проекта двойная лицензия).

## Запустить тесты на своём компьютере

1. Поставьте Go (версия в `go.mod`), Node.js 22 и Docker.
2. Один раз `make web-install`.
3. `make check` — те же проверки, что в CI. `make help` покажет цели поменьше.

## Метки

- `good first issue` — маленькая понятная задача, мейнтейнер поможет.
- `help wanted` — здесь особенно ждём помощи.
- `recipe` — задача по шаблону рецепта, помещается в одну сессию агента.
- `no-tests-needed` — ставит **только мейнтейнер**: снимает требование тестов
  для изменения, которому тест правда не нужен.
- `over-limit` — у нового участника слишком много открытых PR.
