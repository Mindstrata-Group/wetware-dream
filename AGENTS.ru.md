# Правила для участников и их ИИ-агентов

[English](AGENTS.md) — основная версия. Правила одинаковы для людей и агентов.

## Порядок работы

- Одна задача — один PR — одна свежая сессия агента. PR маленькие.
- Не говорить «готово», пока `make check` не зелёный. Вывод — в PR, и всегда
  раздел **«Что не проверено»**.
- Фича или фикс — только с тестом. Фикс бага начинается с теста, который до
  фикса падает.
- Тесты параллельные по умолчанию: `t.Parallel()` в Go, где состояние
  изолировано. Если нельзя — причина комментарием рядом.
- Новый эндпоинт с объектом пользователя — тест «чужой пользователь → 403/404».
- Следуем существующим паттернам. Новый фреймворк, библиотека или сервис —
  только с конкретной причиной в PR.
- Новые тесты и служебные инструменты — на **Go**. Фронтенд тестируется vitest,
  потому что это TypeScript. Новые скрипты на bash/python/node без причины не
  добавляем; bash — только тонкой обвязкой (установщики, вызов Docker).

## Код

- **Комментарии в коде — на английском.** Идентификаторы тоже. Тексты
  интерфейса остаются на языках продукта (русский и английский) — это не
  комментарии. Проверяет `make comments`. (В старом коде ещё есть русские
  комментарии, их переводят; новых не добавляем.)
- Строгий вход: невалидная, просроченная, отозванная кука или кука удалённого
  пользователя → `401` и очистка куки. Гость — только когда куки нет вовсе.
- Миграции — только новыми файлами в `apps/api/sql/`, опубликованные не
  правим; `schema_base.sql` обновляем в том же PR.
- Тексты интерфейса — коротко, простыми словами, о том, что меняется для
  человека. Без технических и процессных терминов.
- Психометрика (подсчёт, нормы, обратные пункты) меняется только вместе с
  эталонным тестом: источник (статья или руководство, со страницей) и
  ожидаемые числа из него. См. docs/verify-analysis.md.

## Данные и секреты

- Никаких реальных данных людей: ни в промптах ИИ, ни в фикстурах, ни в issue,
  ни на скриншотах. Только синтетика (`make dev`, `testdata/`). `make guard`
  ловит похожие на настоящие телефоны, почты, СНИЛС и паспорта.
- Агенту запрещено читать и печатать `.env`, `deploy/.env.prod`, `runner/.env`
  и любые файлы с секретами.
- Не коммитим секреты, сгенерированное (`node_modules`, `.next`, покрытие,
  результаты тестов), дампы и выгрузки.

## Границы для агента

- Деплой, миграции прода и CI не трогаем без явной задачи.
- Не пушим в `main`, не делаем force-push, не мержим.
- Задача неясна — остановиться и спросить, а не угадывать большое изменение.
