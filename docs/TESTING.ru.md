# Тестирование

[English](TESTING.md) — основная версия.

**Правило:** PR открывается только после зелёного `make check` у вас на
компьютере или зелёного CI в вашем форке (со своим [раннером](../runner/README.md)
или без). Вывод прикладывается к PR.

## Одна команда

```bash
make web-install   # один раз
make check
```

`make check` повторяет CI целиком:

| Шаг | Цель | Что проверяет |
|---|---|---|
| Проверки репозитория | `make guard` | gofmt; Go-тесты самих проверок; self-hosted только в форках; безопасный контейнер раннера; actions закреплены по SHA; нет публичных IP, настоящих почт и похожих на настоящие ПДн; шаблон деплоя без конкретной установки |
| Секреты | `make secrets` | gitleaks по коммитам изменения |
| API vet | `make api-vet` | `go vet`, включая интеграционные файлы |
| API unit | `make api-unit` | `go test -race ./...` |
| API integration | `make api-integration` | настоящий Postgres: временный контейнер на порту 55439 или `TEST_DATABASE_URL` |
| Web | `make web-check` | проверка типов, контракт API (OpenAPI), vitest |
| Анонимизатор | `make anonymizer-test` | детектор персональных данных (Python, pytest в локальном venv): правила, эталон, свойства. Единственное исключение из «тесты на Go»: детектор держится на Natasha и pymorphy3 |
| Комментарии | `make comments` | комментарии в коде на английском |
| Тесты изменены | `make tests-touched` | только для PR: изменили логику — изменили тесты |

## Слои тестов

- **Go unit** — чистая логика, быстро, с детектором гонок.
- **Go integration** (`//go:build integration`) — HTTP API против настоящего
  Postgres; каждый тест получает свою базу из шаблона, поэтому тесты идут
  параллельно без общего состояния.
- **Фронтенд** (vitest) — компоненты и помощники.
- **Сквозные** (Playwright, `apps/web/e2e`) — против запущенного сайта после
  `make dev`; в `make check` не входят.
- **Инструменты репозитория** (`tools/`) — Go, табличные тесты.
- **Чистый клон** (джоба CI `Fresh clone: make dev`) — на чистой машине GitHub,
  где `go`/`node`/`npm` подменены заглушками, которые падают, `make dev` должен поднять сайт, API и
  админа для разработки, а повторный `make dev` — тоже пройти. Так обещание
  README «одной командой» проверяется на каждом изменении.

## Как писать тесты

- Новые тесты и инструменты — на Go, фронтенд — vitest.
- `t.Parallel()` по умолчанию; если нельзя — причина комментарием.
- Фикс бага начинается с теста, который без фикса падает.
- Эндпоинт с объектом пользователя — тест «чужой → 403/404».
- Фикстуры — только синтетика (`testdata/README.md`).

В PR джоба падает, если изменена логика, а тесты нет. Если тест правда не
нужен — объясните в PR; мейнтейнер может поставить метку `no-tests-needed`.
