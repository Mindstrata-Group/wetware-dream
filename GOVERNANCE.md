# Governance

**Maintainers** review and merge pull requests, cut releases, and decide on
the roadmap. They are listed in `.github/CODEOWNERS`. The project needs at
least **two** active maintainers: nobody merges their own pull request
without a second review.

**Decisions.** Most changes are decided in the pull request by lazy
consensus: a maintainer approves, nobody objects within a reasonable time.
Larger changes (new dependency or service, database schema direction,
license, security model) start as an issue and need approval of two
maintainers. If maintainers disagree, the lead maintainer decides and writes
down why.

**Becoming a maintainer.** Sustained, good-quality contributions and reviews.
Existing maintainers invite; two must agree.

**Commercial license.** The copyright holders of the Project offer the
commercial license (COMMERCIAL.md). Contributions come in under the CLA, so
this does not change what contributors can do with the AGPL version.

**Code of conduct** applies everywhere in the project: CODE_OF_CONDUCT.md.

**По-русски.** Мейнтейнеры (не меньше двух) принимают PR, выпускают релизы и
решают, куда идёт проект. Свой PR без второго ревью никто не мержит. Обычные
изменения — по умолчанию согласием в PR, крупные — через issue и одобрение
двух мейнтейнеров. Сейчас мейнтейнеры — @kocmocgim (Гайнияров И. М., ведущий
и правообладатель) и @k19mar (Екатерина).
