# Wetware Dream

*More human than human. And now for something completely different.*

[English version](README.md)

Wetware Dream — открытое ядро **Mindstrata** (Стратум): веб-сервис для бесед
с ИИ-ассистентом по сценариям. Режимы разговора с психологической основой,
которые пишут эксперты, тарифы и промокоды, оплата, уведомления и админка,
чтобы всем этим управлять.

- `apps/api` — API на Go (PostgreSQL, вход, чат, шлюзы ИИ, оплата, админка).
- `apps/web` — фронтенд на Next.js (интерфейс на русском и английском).
- `apps/mcp-admin` — MCP-сервер: ИИ-агенты выполняют команды администратора.
- `deploy/` — шаблон для сервера: одна машина, HTTPS автоматически.
- `runner/` — необязательный раннер тестов для форков участников.
- `tools/` — проверки репозитория и помощники на Go.

## Запустить у себя одной командой

Нужны Docker и `make` — больше ничего: ни Go, ни Node. Дальше:

```bash
make dev
```

При первом запуске команда сама создаст `.env` со случайными секретами,
поднимет всё, добавит выдуманных клиентов и диалоги и напечатает логин только
для разработки (`admin@example.com`). Откройте http://localhost:3000.
`make dev-down` останавливает, данные сохраняются. Первая сборка — несколько
минут.

Заняты порты 3000, 18080 или 55433? Задайте `WEB_PORT`, `API_PORT`, `DB_PORT`
в `.env` (и поправьте под них `PUBLIC_WEB_URL` / `PUBLIC_API_URL`).

Без `make` или без тестовых данных:

```bash
cp .env.example .env        # поменяйте три значения change-me
docker compose up -d --build
```

Именно этот путь на каждом изменении проверяет джоба CI `Fresh clone: make dev`
на чистой машине.

## Стать администратором

Первый администратор создаётся один раз ключом `BOOTSTRAP_ADMIN_TOKEN` из `.env`:

```bash
curl -X POST http://localhost:18080/api/bootstrap/admin \
  -H "X-Bootstrap-Token: <BOOTSTRAP_ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"длинный-пароль"}'
```

После этого запрос отказывает: администратор уже есть. Войдите на сайт с этой
почтой и паролем.

## Подключить ИИ

Ключи ИИ **не** задаются переменными окружения. В админке откройте
**Оркестрация → AI** и добавьте шлюз: OpenAI-совместимый (OpenAI, OpenRouter
и подобные), Anthropic или Google Gemini — адрес и ключ. Ключи хранятся в
базе, поменять их можно без передеплоя. Потом выберите шлюз для каждого режима.

## Поставить на сервер

В `deploy/` лежит шаблон с Caddy и автоматическим HTTPS, а
[docs/deploy.ru.md](docs/deploy.ru.md) по шагам проводит через первый запуск на
VPS, миграции, бэкапы, обновление и откат.

## Участие

Начните с [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md). Коротко: форк → при
желании [раннер на своём компьютере](runner/README.md) → зелёный `make check`
→ PR по шаблону. Работать с ИИ-агентом можно: он читает
[AGENTS.md](AGENTS.ru.md), а [AI_POLICY.md](AI_POLICY.md) объясняет, чего мы
ждём от таких PR. Не программист? Начните с [docs/overview.md](docs/overview.md)
и [рецептов](docs/recipes/).
